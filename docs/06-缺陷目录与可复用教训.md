> 本项目的构建前硬门与离线判据，**几乎全部来自真实故障**——不是设计出来的，是被打出来的。
> 这份文档按"缺陷族"组织：同一族会在不同地方反复出现，认得出形态比记住某一个 bug 有用。
>
> 读法：先看第 1 节六族总表，再按需查详情。**接手前务必读完第 1 节和第 5 节。**

## 2. A 族：本机绿 ≠ 交付物绿（最高频）

### A1 改了没提交，判据跑的是工作区
- **现象**：本机全绿，CI 红。
- **根因**：本机验证的是工作区，CI 检出并打包的是**提交**——两份内容不是同一份。
- **修法**：硬门直接点名并给出 `git commit <文件>` 命令。
- **教训**：**"验证结论对交付没有担保"是最贵的一类错**。任何"我本机跑过了"都要问一句：
  跑的那份，交付机上有没有？
- **本段又犯了一次，形态不同**：改完判据本身（`debug/doc_hygiene_offline_test.py`）先去跑全量
  批跑，结果 frozen 里第 24 条点名「工作区改过没提交」——那一批的结论只对当前工作区成立。
  这不是误报，是它该做的事；**正确顺序是先点名提交、再跑全量**（拿它当噪声划掉就等于
  把唯一能拦住“验的不是同一份”的把手拆了）。

### A2 判据没入库（第 20 条 `check_regression_suites_tracked`）
- **现象**：写完判据当天跑绿，之后随包代码怎么改都不红。
- **实例**：riskbird_build 的 13 个套件此前压根不在批跑表里。
- **修法**：交付目录按命名约定 `test_*_offline.py` **自动发现**；`debug/` 手写但配完整性判据。
- **教训**：**"要记得登记"这条要求本身就是缺陷来源**。约定 + 带理由的排除表才是解。

### A3 开发机绝对路径混进交付链（第 21/25 条）
- **本段实例**：两份 `.command` 双击入口写死 `/Users/xxx/PythonDemo/.venv/bin/python`。
  换台机器就退到系统 python3 → 那里没 PyQt5 → **症状是"窗口一闪就没了"**，
  报的还是 import error 而不是"环境没建"。
- **修法**：按脚本自身位置找 `../.venv`，并且**探测 `import PyQt5`** 而不是只探测解释器存在。
- **自审追加教训**：我修这一处时，自己又把 `$HOME/Desktop/PythonDemo` 加进了候选——
  **修 bug 时顺手引入同族 bug 是会发生的**，改完要用门扫一遍（第 25 条现在也扫这两个入口）。

### A4 workflow 步间不继承 cwd（第 41 条）
- **现象**：2026-11-19 云端 Windows 与 Mac 两路**同时**读不到产物体积，本机怎么跑都绿。
- **教训**：CI 的每一步是独立进程。跨步状态要么显式传，要么每步自己 `cd`。

### A5 生成器与产物分叉
- **现象**：改了 `build-b2bcollect-legacy.yml` 忘了改 `debug/gen_legacy_workflow.py`，
  红话给的修法（"重跑生成器"）在**干净克隆里根本跑不了**（生成器没入库）。
- **修法**：判据里同时钉"生成器在提交里"与"生成器输出与 yml 逐字节相同"。

## 3. C 族：把"测不到"当"没有"（本段最贵的一族）

> 这一族的特殊性：它长得像"更安全"（fail-closed），所以会被有意无意地选错。
> **但关掉一个真功能的代价，远大于一句不精确的话。**

### C1 `sm_binary()` 第一版：unknown 与 absent 混成同一个 None（本段）
- **场景**：`create()` 本地驱动全落空时回退 Selenium Manager；要先判断这个组件在不在位。
- **错法**：import 失败（selenium 装法不在预期里）→ 返回 None；实测没有 → 也返回 None。
  于是"问不到"也被当成"确认没有"，**拦停了回退**。
- **后果**：在假 selenium 夹具、精简环境里，把用户唯一的联网兜底整条关掉。
- **怎么被抓到**：riskbird **既有**套件（用假 `sys.modules["selenium"]`）当场打红。
- **修法**：三态 `("present" | "absent" | "unknown", path)`——**只拦 absent**，
  unknown 保留原路径 + 一句诚实限定（"本机问不到它在不在位，能不能成看这一次的结果"）。
- **教训**：**fail-closed 的方向要对**。不确定时有三个出路（放行 / 拦停 / 说话但放行），
  默认选"拦停"看着最负责，实际是把不确定性转嫁给用户。

### C2 PE 地板门 43 条假红（本段）
- **现象**：兼容通道 run#2 报 49 条不合格，看着像产物有大问题。
- **真相**：A 类 43 条是**门自己**把"导出表读不出""没有导入表"当成"不合格"；
  只有 B 类 6 条是真发现。
- **同源修法**：门的红话也按三态分格——**实测没有 / 读不出 / 没东西可实测**。

### C3 `presence` 检查不分平台（本段）
- **错法**：`glob(selenium-manager*)` 找二进制。
- **事实**：selenium 的 wheel 会把**所有平台**的二进制一起装机——Mac 上 glob 拿到
  `linux-arm64` 那一份，判"退路在位"，而那个文件在本机**根本无法执行**。
- **教训**：**"存在"不等于"本平台可执行"**。凡是找二进制的代码都要问这一句。

### C4 空视野报绿
- **形态**：`check_py38_floor(sources=[])` 若返回"没有不合格"，就是一句谎话。
- **判据**：空集合必须自己红（第 20 条同族思路）。

### C5 下载完整性：把"没拿到"读成"没有"（本段）
- **实例**：`ci_status.sh` 把 API 响应写进 `debug/ci_status.json`，curl 断在半路时
  **截断的 JSON 原地留着**，下次 `cat` 它就是垃圾，而现场看着像成功过。
- **修法**：不落盘（`-o -` 走 stdout）。**续传在这个语义下反而是错的**——
  续上一轮的半截缓存比整段重下更骗人。
- **配套**：`-f` 让 HTTP 4xx/5xx 直接失败，否则 404 的错误体会被当成"没有跑过的记录"。

## 4. D 族：判据自身有缺陷（只有变异复验能抓到）

> **一条从未红过的判据，你不知道它是"没问题"还是"没在看"。**

| 实例 | 缺陷形态 | 后果 | 修法 |
| --- | --- | --- | --- |
| DH 节组 10d（本段） | 一条模糊子串断言同时覆盖三个分支 | 分不清哪条分支放的红 = **假绿** | 拆成三条各自钉死 |
| frozen 组 12（本段） | 切片跨了 doctor/冒烟/编安装包三步 | 把合法的 `OUT_FILE` 当嫌疑对象 = **假红** | `_body(name)` 只取单步正文 |
| `_assert_eq`（本段） | 通过时也用 `!r` 打两边 | 比 40KB yml 字节时日志灌到 ~90KB，真信息被埋 | if/else + 报**首差异字节号**（日志 11KB） |
| 判定行绕计数器 | 裸 `print` 打"通过" | 总数失真（3357/14 这种数不可信） | 报告层收口：判定行不许绕开计数器 |
| 第 42 条自身四缺陷（上段） | 尾部空行话术 / 没剥注释 / 编码头 / 内联 python | 门读注释 = 门在判文案 → **假红** | 只判代码行 |
| N2 / N4（需求 8） | 夹具打不到炸点 | 变异不红 = 判据没在工作 | 补交叉核对变异 |
| 指路节号走不通 | 注释写"见第 N 条"但 N 不存在/不对 | 排障时被指向空处 | 第 12 条 `check_section_pointer_references` |
| 看门狗取不到就裸跑（第 11 节） | `command -v timeout` 空 → 静默降级成不设时限 | **挂死被读成 PASS**（比红更贵：屏幕上写着通过） | 内置 bash 看门狗兜底 + 降级必须当场出声 |
| 断言把「跑判据的解释器版本」当常数（第 11 节） | 要求 `fstrings > 100`，而地板那档 3.11 恒为 0 | 本机绿、**门禁档必红**（要求「跑门比自家地板更先进」） | 钉性质不钉版本：换版本无关证据兼做下限 + 分情形要求 |
| 第 4 次恒真断言（第 11 节） | `x != "env" or True`，拔掉 `or True` 后发现方向还写反了 | 这条从未判过任何东西，连「反了」都暴露不了 | 变异复验时**必须逐格拔牙**，不能只拔新写的那几格 |

**标准动作**（写判据后立刻做）：
```
把修复逐个退回原样 → 对应判据必须精准变红 → 逐字节还原（git diff 必须空）→ 复跑回全绿
```

## 5. 五条可以直接继承的工程原则

1. **少一个文件不会报错，只会少一个功能**——所以结构完整性必须在构建**前**拦（第 1 条门）。
2. **每修一个真故障，补一道会红的闸**，且闸必须写明由来（本仓库每一道都如此；条数见 `03` §1 的取数命令）。
3. **不确定时分三格说**：确认没有 / 读不出 / 没东西可实测。只有第一格允许拦停。
4. **判据要能被打破**：新判据必须通过"退回原样会红"的变异复验，否则视为假绿。
5. **报告与判定必须同源**：计数器、相对路径、失败原因、"这一路在等谁"那盏灯，
   都只许一个把手（第 24/30/36/38 条）——两处表述迟早分叉，分叉后人就开始跳过日志。

## 6. E 族：兼容性地基（需求 8/10 的主战场）

| 问题 | 真相 | 收口 |
| --- | --- | --- |
| Win7 装不上 | CPython 3.9+ 产物引入 `api-ms-win-core-path`——但它是**运行期延迟加载，不在导入表里**，所以 PE 地板、窗口冒烟、自报对拍**全都看不出来** | 唯一能判的是**解释器自报**（第 42 条双解释器体检） |
| 装完缺库 | 缺 VC++ redist / OpenSSL 1.1 命名不在别名表 | 安装器随包补装（10A `a80ca17`）；别名表补（`f53b7b1`） |

| "CI 全绿、用户开不了" | `doctor` 刻意不碰 Qt，Qt 起不来它测不到 | 补只读包窗口冒烟（同上） |
| 数窗口不可信 | 锁屏/远程会话下对所有进程都报 0 | 只认产物自己写进 `launch_history.log` 的 `shown` 行 |
| 老系统 ChromeDriver | Win7 Chrome 最高 109，随包驱动不能带新的 | `fetch_chromedrivers.py` 按地板封顶（第 10 步"Win7 那一档：最高 109"） |

## 7. F 族：时序与并发

- **F1 迟到回调覆盖权限判定**（需求 6，本段修）：权限判定与建窗有竞争，
  回调晚到会把已定的档改回去。修法：加**同步定档时刻地标**，晚到的回调不许改判。
- **F2 批跑抖动**（`816a5bf`）：`gui_store` 排队投递无地标、`edition` 心跳导致断言时有时无。
  **抖动必须根治而不是加重试**——重试会把真缺陷平均掉。
- **F3 Qt 退出顺序**（第 17 条）：`sys.exit(app.exec_())` 让窗口在解释器收尾时才析构，
  症状是"功能都对但退出码在抖"。必须 `rc = app.exec_()` → hide + None → `sys.exit(rc)`。
- **F4 trap 处理器**（第 33 条）：trap 触发时它调到的每个函数必须**已经定义**。
  函数写在 trap 后面 = 拿"脚本一定能跑到那一行"当隐含前提。

## 8. 本段（交接复核）新记的四条

写下来是因为它们**都是我自己造的**，而"自己造的错"最难被 review 发现：

1. 文档里写"上百 GB"——**未实测的估算**。实测 8.6 GB。凡数字必附复跑命令。
2. 文档里写"本机必须装 Python 3.8"——**从"CI 需要"推断成"开发机需要"**。
   实际 3.8/3.11 只在云端 Windows runner；本地硬装在 arm64 上是个坑且零收益。
3. 文档里把 `enf_clean` / `phonenumbers` 判成"可归档/可删"——**只 grep 了 import，
   没查 `--add-data` 与 `--hidden-import`**。差点写出会让人弄坏清洗链的指引。
4. 中文形近错替三次（豁→`貁`、绝→`绞`、接→`进`）。靠**肉眼 review 抓不全**，
   最后是靠"以既有语料为合法字表、扫新文档里的生面孔"这个脚本抓净的（共 6 个字，全对）。

> 这四条的共同点：**结论看起来很有依据，但依据的采集方式有系统性盲区。**
> 自审不是"再看一遍"，是**换一个采集口径重取一次**。

## 9. 本段（同机交接）新记的四条

同样都是自己造的，而且全都长在**“声称是证据的那句话”**上：

1. **假证据源**：交接话术里写「`check_packaging_manifest.py | tail -3` 那一行报的是当前
   门禁道数」，而硬门的尾行只报结论、不报任何数。它不是数字过期，是从未存在过的取证路径
   ——下一位拿着它永远对不上账，还会怀疑是自己环境坏。定性办法：**每一句“证据”都要当场跑
   一次，看它真能回答那个问题**，而不是看它格式对不对。
2. **临时发明口径**：为了取“门禁多少道”我写了一条 `grep -cE '^[0-9]+ check_…'`，数到 34；
   仓库里 `己3` 拿 AST 对拍出来的44。差 10 道。同一个问题永远**先找仓库已有的那个真源**，
   新造一把尺就是开一个会漂的第二口径。
3. **状态对拍门的两个局限**（本轮被它误归因一次）：① 哈希对拍分不开“没写”与“写了同样的
   字节”（缓存内容相同时 mtime 会变、hash 不变）；② 它按“当前正在跑的那一路”记账，
   而**外部活进程**（上一轮留给用户测试的工具本体还开着，60s TTL 自刷缓存）的写入会被记到
   套件名下。定性靠：关掉所有活客户端复跑一次 + `lsof`/mtime 取证，而不是只信它那句归属。
   （本例结论：复跑后 78 份全绿——那一轮的红是误归因；隔离补上仍然保留，因为它同时挡住了真泄漏。）
4. **正控被自己拦下**：为了证明“这一路真的会写缓存”，我把隔离环境变量摘了——结果套件
   在新增的那句 `_state_dir()` 自证上当场中止，根本没跑到写点，于是“缓存没变”是一条**空结论**。
   正控要能区分“没发生”与“没跑到”：改成把沙箱固定到一个临时目录、看里面有没有长出缓存，
   才是有效对照。

> 这一节的共同形状：**“我验了”与“验到了”是两件事。** 只要一次实验在某个前置步骤就中止，
> 它后面报出的全部“通过”都不作数。

## 10. 本段（推送后四条发版通道同时红）新记的四条

这一轮的特殊之处：响红的是**我自己为交接建的那条门**（第 44 条），而且它把 Win / Mac /
Win7 兼容 / 干净检出回归四条通道一起堵死了。以下四条都有实测编号可查（判据在
`debug/handover_closure_offline_test.py` 甲6b～甲6e，变异驱动跑完后删除）。

1. **豁免条件本身不许依赖“本机才有”**（A 族第 N 次付学费，这次付在门上）。第 44 条要给
   `b2bcollect_build/config.json` 这类凭据指路不被喊 git add，用条件是“它在 `git ls-files --others
   --ignored` 里”。但那份清单**只列磁盘上真实存在**的被忽略文件——干净检出里这个文件根本没被
   checkout（它就是被拦着才不入库的）→ 豁免蒸发 → 本机全绿、CI 报“死路”。改用
   `git check-ignore --no-index --stdin`：只查规则、既不查磁盘也不查索引，两台机器必然同一答案。
   换口径前先实测两套结果差异（本仓库 99898 条被忽略路径，老有新无 0 条）才敢动。
   → 证人：甲6b（被规则忽略但磁盘上没有）。
2. **夹具不许比被它替掉的实现更宽容**。本段第一个致命细节：变异 M1（把旧实现抄回去）第一轮
   **一条都没杀红**——因为夹具把 `_path_set` 打成“无条件返回声明的忽略集”，而真命令的语义是
   “只列磁盘上存在的”。夹具替得比实现干净，等于把被测缺陷从测试里隐掉了。改 `{p for p in
   ignored if (tmp/p).exists()}` 后 M1 立刻精准响在甲6b。
   → 纪律：**替代某个助手时，要复刻它的关键语义而不是只给一个方便的答案**。
3. **顺手补的那格最容易是恒真断言**。甲6d-3 初版写作 `… is not None and _world(…) and True`：
   既不真跑工作树外的 git，右边又是字面量 True——生下来就是绿的、永远绿。这是本仓库第三次在
   自己新写的判据里发现此类（前两次见第 8/9 节的恒真夹具）。修：真 `git init` 一份小仓库，
   拿真助手跑“不存在但被规则拦住”与“工作树外报 None”两个真实分支。

## 11. 本段（干净检出泳道 run#2 的 8 条红）新记的六条

这一轮的入口数据很清楚：云端那条**不路径过滤、每次 push 都跑**的干净检出回归（run#2）报了
8 条 frozen 红 + 一份被写脏的状态文件。逐条取证后：**没有一条能在开发机上复现**——它们全是

1. **静默降级比直接不支持更危险**（B 族）。`run_offline_regression.sh` 旧写法：

   那两支会静默分叉）；**降级必须当场在屏幕上承认**（否则下一个人把“没有保护”读成“不需要保护”）；

   修：换一条与版本无关的同路证据（`escape_files`）兼做下限，f-string 那一档按
   `hasattr(tokenize, "FSTRING_START")` **分情形**要求——两边都不许拿“本机判不了”顶替

   方式也要按“目标机怎么建”复刻**——要么挂上 `.venv`，要么用 `PY=<绝对路径>` 覆盖（入口

## 12. 交付自审阶段新记的三条（拿交接链自己对现实对账时跑出来的）

> 本节不是云端报的，也不是本机批跑报的——是**拿自己刚写的判据去做变异复验**时跑出来的。

2. **一次完整的假复验：注入根本没发生**（D 族）。变异台第一版用 `perl -pe 's/\u7ecd/../'` 做中文注入，
   而 Perl 不解释 `\u`（那是 Python/JS 的写法）——四路替换全是空操作，输出却是“都不红”。
   如果我当时按“判据无牙”去修判据，就是拿一个不存在的缺陷改坏一份好文件。
   接住我的是两个反常信号：**五路里只有一路红**（变异台不可能这么糟），以及 M3 那条纯 ASCII
   注入正常开火——两者一对比就能定位到“不是判据问题，是注入问题”。
   修：注入改用 Python 字符串，并且**每路注入前先 `assert count(old) == 1`**：注入没发生就当场报错，
   不让空操作冒充结论。另：判定语义也从“只允许期望那格红”改成“**期望那格必须在场**，连带红只提示”
   （一次破坏同时让几格红是正常的，把它们当噪声判失败会诱使后人拆弱判据）。
   → 可迁移的做法：变异台自己的每一路都要有“注入生效的现场证据”；**工具链陷阱不区分消费方**，
   写测试脚本的 shell 和写产品的 shell 一样会错。

3. **只靠一把把手，会把“抓不到”当成“没错”**（D 族）。本轮我自己往文档里写了十来处形近/音近错字

   了其中关键几处——因为它只报“仓库从没用过的字”，而“绍”在两份 `customer_library_cleaner.py`
   里早就在用（这句已经固化成辛4，不靠口头承诺）。
   修：新增 `KNOWN_TYPOS` 样本黑名单（每一轮人工抓到的错字都落成一条，带出处），配三件配套：
   辛2 正控（每条必须能把自己判出来）、辛5/辛6 负控（一段干净中文必须一个都不命中，
   且底文真含高频词）、辛7 视野证人。这是行业里“**lint 规则集随事故增长**”的做法。
   **写完这一节的当天又犯了三处**（`自名单`/`捧住`/把“扫”写成形近的那个字），全部靠辛1 重跑才抓出来——
   其中一处根本不是我想写的字，而是**编辑工具写入中文时的单字变形**（同一短语在仓库里从没出现过，
   而那个字本身在代码里用过 5 次，所以丙2 也看不见）。→ 不要把黑名单当完备把手：它只覆盖
   被钉住的形状；真正的口径是“**只要刚写过中文，交出去前就重跑一次本判据**”，而不是“我 review 过了”。
   → 两条纪律：**错字类反馈只靠“扫生面孔”一类机械把手不够**，它天然看不到“字合法、位置错”；
   而每当一轮 review 抓到一个新错，就要问“它能不能变成一条不可回退的判据”，不能只改那一处。
   → 但**不是所有变形字都要进黑名单**：本轮另外两处（把“不出网”写成含“岜”、把“造不出”
   写成含“嗘”）实测**不在 `.py/.md` 语料里**（判据的语料只取这两种后缀，第 90 行，

## 13. 推送之后才拿得到的几条（本节随实测追加，标题里的“两条”是初版规模）

1. **把“目录白名单”读成“文件性质白名单”，台账就写反了一句因果**（B 族）。我在 `05` §2 ⑧ 与

2. **一条“判据全绿”的新门，在真实产物上第一次跑就红——而且红的是产品**（E 族 + D 族）。

   第一次跑才算被验过**（离线样本只能证“门会响”，不能证“真包里有/没有那批东西”）；
   而这类“构建全绿、只在老机器上当场拒载”的形状，正是这条门存在的理由。
   → 可迁移的做法：兼容性地基的检查必须落在**产物字节**那一侧（PE 头、导入表、真实镜像），
   而不是构建参数那一侧；并且新门入库时要问一句“它在今天真实的交付物上跑过了吗”，

3. **把“本机绿、云端红”随手定性成“判据赌环境”，而现场字符串本身就在反驳我**（D 族）。

   同一族的上一笔学费在 `05` §3 第 12 项，修法与三步顺序都写在那里。

4. **“失败 1 格”可能是“半套未跑”——两种失败语义共用一个列位**（D 族）。
   云端那一跑里 `local_scan` 与 `acl_levels` 都只算“一条红”，但形状不同：后者用

   （第 52 行）——**一红就中止整个脚本**，⑨ 之后的格全部零覆盖。汇总行把它们

   （失败信息越完整，下一轮越不需要重跑）；真要 fail-fast，就得在输出里说清“从这里
   往下没跑”，否则它会在报表里伪装成“基本ok”。
