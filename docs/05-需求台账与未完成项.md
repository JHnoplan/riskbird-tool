## 4. 用户明确表达过的工作方式要求（**必须延续**）

这几条不是需求，是**协作契约**，接手后照做会顺，违反会被反复退回：

1. **每一步骤都要中文描述**——"不然不知道你在处理什么，到哪一步了"。
   长任务期间要主动给进度叙述，不要闷头跑。
2. **全程自审**——自己写的东西要自己找错。本项目的自审已经抓到过：
   判据自身缺陷（切片跨步骤、日志污染、`presence` 不分平台）、
   文档里的未验证数字、中文形近错字。**自审要产出证据，不是"我检查过了"。**
3. **完善后打开工具给用户测试**——交付的终点是用户能看到界面，不是测试通过。
4. **结合国内外顶尖大厂的技术和思想**——本项目落地的对应实践是：
   构建前门禁（shift-left）、变异测试（`mutation testing`）、
   单一真源（SSOT）、fail-closed 但**区分"测不到"与"没有"**、
   固定直链 + 清单驱动更新（企业软件分发惯例）。
5. **授权已给**：按需求分批提交；每次收尾都推送 origin/main。
