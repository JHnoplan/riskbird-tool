### 1.1 `enf_clean/` 的真实地位（新人极易误判，这里写清）

名字叫「清洗小库」，看着像历史产物，**但它是 b2bcollect 的进包运行期依赖**：

```
workflow:  --add-data "..\enf_clean;enf_clean"                ← 整目录进包
           --hidden-import enf_clean.normalize --hidden-import enf_clean.phone
           --hidden-import phonenumbers                        ← 紧跟其后，不是可有可无
运行期:  b2bcollect_build/enhanced_cleaner.py:36-40
           from enf_clean.normalize import …  /  from enf_clean.phone import Audit, parse_phone_cell
再往下：       enf_clean/phone.py:14  →  import phonenumbers as pn
硬门登记： CALLERS["enf_clean"] = "清洗子包源码目录（缺它 = enhanced_cleaner 整条链路降级）"
```

两个容易踩空的点（都是实测出来的）：
- **`phonenumbers` 不能从依赖清单删**。它是经 `enf_clean.phone` 进入运行链的真依赖
  （本段交接复核时曾误判成"只被未入库目录使用"，差一点就写进文档了，见 `05` 第 3 节）。
- **`pandas` 确实可以剪**：`enf_clean` 里只有 `clean_three_files.py` 等三份 import 它，
  而那三份是**数据**（随包但运行期没人 import）。进包的只有 `normalize` 与 `phone`。
  这一格「同目录、同随包、命运不同」止于 PyInstaller 只看真 import 链——**删东西前先把链跑一遍**。

## 3. 一次采集的完整数据流（照着它读代码最快）

```
用户在 GUI 填关键词/省份 → parallel_session 起 8 通道
  ├─ 裸 HTTP 通道（7 个站）：*_crawler.py 直接 requests 拉列表 → 详情
  └─ 需浏览器的通道（1688、企知道补采）：site_adapters 复用 riskbird/ali1688 的爬虫
        └─ chrome_driver.create()：本地驱动优先，全落空才回退 Selenium Manager
        └─ block_guard：撞风控就等待/移交，不硬闯
              ↓ 每站产出「原始记录 + 通道账（站方回了几条 / 采到几条 / 为什么没有）」
ingest_cleaning（写侧清洗：字段收口、号码/邮箱规范化、text_shape 单一把手）
  → dedup_engine（重复判定打分）
  → pool_store（SQLite + FTS5 物化成 Gold 层）
  → enrich_waterfall（缺字段按成本升序逐级问：站内 → 官网回采 website_contact → 拼音候选 → AI）
  → 导出 Excel（openpyxl，无 pandas）/ oss_pool_client 上传团队池
```

**每一步都有对应离线判据**，命名一律 `test_*_offline.py`（自动进批跑）。

## 4. 四块支撑能力的关键设计

### 4.1 权限与档位（需求 1/4/6 的落点）
- `access_guard.py`：账号权限 = **云展绑定 + OSS 白名单（分等级）+ 单点登录设备绑定**。
- `edition.py`：交付档位 `lite`（丐版）/ `pro`（内部版）。**权限 1 的账号只应看到基础功能**。
- 已修缺陷（务必了解，否则会写回）：**迟到回调覆盖权限判定**——判定与建窗有时序竞争，
  现在用"同步定档时刻地标"钉住（提交 `816a5bf` 之前那批）。判据是 F3/F4 组（22 条）。

### 4.2 版本与自动更新（需求 2）
- `tool_version.py` 是版本号**唯一真源**；构建戳 `version.json` 由 CI 现生成、绝不入库
  （`.gitignore` 里），否则"本地一份 CI 一份，谁生效看不出来"。
- 发布侧：`make_release_manifest.py` 生成 `latest_windows.json` / `latest_mac_arm64.json`，
  `upload_release_to_oss.py` 覆盖上传到固定 OSS 直链。
- `check_artifact_selfreport.py` 把"产物自报版本"与"CI 注入版本"逐条对拍。

### 4.3 崩溃取证（需求 8：Windows 搜索采购商后崩溃）
- `crash_forensics.py`：装钩子 + 面包屑 + 全线程栈 + 脱敏，**零抛出**是硬要求
  （取证模块自己崩了就等于没有）。
- 根因把手：`text_shape.cell_text` / `cell_join`（表格单元格里塞进非预期类型）。
- 离线判据：`test_crash_forensics_offline.py`（192 项，含 N 段钩子链回归）。

### 4.4 配置与密钥（需求 10 的地基）
`tool_config.py` 五级解析链，**顺序即优先级**（源码 docstring 第 17-26 行）：

```
0. 环境变量 OSS_ACCESS_KEY_ID / OSS_ACCESS_KEY_SECRET / DEEPSEEK_API_KEY
1. B2B_CONFIG_FILE 指定的文件
2. exe 同级 config.json          ← 不发新版也能就地修好一台机器
3. 随包 config.json（_MEIPASS / 模块目录）
4. ~/.b2bcollect/config.json     ← 界面「保存密钥」的落点，打包态唯一保证可写的一级
5. 开发态额外看仓库根；frozen 态绝不越界找任何机器专属路径
```

**密钥必须成组**（`KEY_GROUPS`）：OSS 的 id 与 secret 只在**同一级里凑齐**才算这级提供了它，
"新 id + 旧 secret"会被整级跳过并记进 warnings。

## 5. 跨目录复用：本项目最容易踩的机制

b2bcollect 不 fork 爬虫代码，而是把 `riskbird_build/`、`ali1688_build/` 的源文件
**以 --add-data 形式装进自己的包**。登记在 `site_adapters.EXTERNAL_MODULES`（7 份）：

```
ali1688_build/ali1688_crawler.py      riskbird_build/qizhidao_crawler.py
riskbird_build/block_guard.py         riskbird_build/chrome_driver.py
riskbird_build/riskbird_crawler_v2.py riskbird_build/aiqicha_crawler_v2.py
riskbird_build/runtime_paths.py       ← 漏了它不是少一个平台，而是开机即崩
```

由此产生两个必须守住的规矩：

1. **同名拷贝分叉**：`customer_library_cleaner.py` 在 3 个目录各有一份、
   `yzd_client.py`/`task_registry.py` 在 2 个目录各有一份。打包态按 `sys.path` 顺序解析，
   谁在前面生效**看不出来**——第 2 道硬门 `check_shared_source` 与尾门
   `check_win_payload_manifest` 就是在管"分叉必须在案"。
   **改这类文件时，先确认你改的是运行期真正生效的那一份。**
2. **改了 riskbird/ali1688 的代码 = 改了 b2bcollect 的交付物**，必须过 b2bcollect 的
   构建前硬门与 frozen 回归（第 20 条那一路会告诉你进包输入是否都在提交里）。

## 7. 术语表（代码里反复出现的黑话）

| 词 | 含义 |
| --- | --- |
| **硬门 / 闸** | `check_packaging_manifest.py` 里的 42 项构建前检查，任何一条不合格就不许开建 |
| **判据** | 离线回归断言（`test_*_offline.py`），一条判据 = 一个真实故障换来的永久提醒 |
| **节**（如 DH 节） | `test_frozen_delivery_offline.py` 内部的分组单位 |
| **变异复验** | 把修复逐个退回原样，确认新判据真的会红；只有"能被打红"的判据算有效 |
| **假绿** | 判据跑了但打不到炸点（夹具形状不对、切片范围太宽），看着绿其实没保护 |
| **通道账** | 每一路采集的产出记账：站方回了几条 / 采到几条 / 为什么没有 |
| **档位 / edition** | `lite` 丐版、`pro` 内部版；由权限等级决定可见功能 |
| **进包闭包** | 从入口模块沿 import 能走到的全部文件，PyInstaller 的真实输入 |
| **地板** | 兼容下限：Python 3.8 语法地板、PE 子系统版本地板、Windows 6.1 安装器地板 |

## 8. 重跑本文件的取数脚本

模块职责随代码走，这两段命令能重建第 1、2 节的数据：

```bash
# 规模与职责（AST 读 docstring 首行 + 行数）
.venv/bin/python - <<'PY'
import ast, subprocess
from pathlib import Path
files = subprocess.run(["git","ls-files","*.py"],capture_output=True,text=True).stdout.split()
for d in ("b2bcollect_build","riskbird_build","ali1688_build",".github/scripts","enf_clean","debug"):
    rows=[]
    for f in files:
        if not f.startswith(d+"/"): continue
        p=Path(f)
        if not p.exists(): continue                      # 已跟踪但工作区没有：跳过而不是炸
        txt=p.read_text(encoding="utf-8",errors="replace")
        doc=ast.get_docstring(ast.parse(txt)) or ""
        first=next((l.strip() for l in doc.splitlines() if l.strip()),"(无 docstring)")
        rows.append((len(txt.splitlines()),f[len(d)+1:],first[:76]))
    print(f"\n### {d}/  {len(rows)} 份 / {sum(r[0] for r in rows)} 行")
    for n,f,first in sorted(rows,reverse=True): print(f"{n:6d} {f:40s} {first}")
PY

# 顶层依赖边（方向=谁 import 谁；把 targets 换成你要看的模块）
.venv/bin/python - <<'PY'
import ast
from pathlib import Path
local = set()
for d in ("b2bcollect_build", "riskbird_build", "ali1688_build"):
    local |= {p.stem for p in Path(d).glob("*.py")}
targets = ["b2bcollect_build/b2bcollect_gui.py", "b2bcollect_build/parallel_session.py",
           "b2bcollect_build/site_adapters.py", "b2bcollect_build/access_guard.py"]
for t in targets:
    p = Path(t)
    if not p.exists():
        print("缺:", t); continue
    deps = set()
    for n in ast.walk(ast.parse(p.read_text(encoding="utf-8"))):
        if isinstance(n, ast.Import):
            deps |= {a.name.split(".")[0] for a in n.names if a.name.split(".")[0] in local}
        elif isinstance(n, ast.ImportFrom) and n.module:
            if n.module.split(".")[0] in local:
                deps.add(n.module.split(".")[0])
    print(f"{p.name:26s} -> {', '.join(sorted(deps)) or '(无本仓内部顶层依赖)'}")
PY
```
