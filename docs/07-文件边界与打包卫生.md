# 07 · 文件边界与打包卫生

> 回答两个问题：**发新机器必须带什么** / **工作区那一堆东西哪些能删**。
> 所有数字都是 2026-11-20 实测（附复跑命令）。

---

## 1. 三个层次，先分清楚

```
层次一：仓库里已跟踪 ──────────── 全部代码/判据/夹具/交接文档  ← 这才是「项目」，git clone 就能拿到
层次二：未跟踪、也没被 .gitignore 忽略 ← 「危险区」：一次 git add -A 就进历史
层次三：未跟踪、已被 .gitignore 忽略 ─── 可再生物（.venv、缓存、构建中间物）
```

> ⚠️ **层次三不是“天然安全”**：它只保证“不会被误 add”，不保证“不会被写脏或凭空创建”。
> 本轮实测到两处：套件调一个**首调即写盘**的公开接口取设备标识，就在干净检出里
> 创建出了 `b2bcollect_build/acl/`——它属于层次三，所以 `git status` 依然干净，
> **看 status 发现不了**。口径：套件碰任何运行态落点前，先用 `B2B_STATE_DIR` 把默认落点
> 钉到临时目录并当场自证；批跑收尾的状态对拍正是判这个的（成因与教训见 `06` 第 11 节）。

> 三个层次各自多少份**不在本文抄数字**：它们随每一次提交变，抄进来那天就开始
> 烂。下面三条命令就是现行口径，要哪个数当场跑：

```bash
git ls-files | wc -l                                          # 层次一
git -c core.quotepath=off ls-files --others --exclude-standard | wc -l   # 层次二
git ls-files --others --ignored --exclude-standard | wc -l                 # 层次三
```

> ⚠️ **统计中文文件名必须加 `-c core.quotepath=off`**。
> 不加时 git 会把 `打包说明.md` 输出成 `"\346\211\223..."`（**以引号结尾**），
> 于是 `grep '\.md$'` 一条都匹配不上。本段我就踩过：漏统计了根目录全部中文文档，
> 差点得出"根目录没有未入库资料"的错误结论。

## 4. `*.spec` 为什么不在仓库里（不是遗漏）

`*.spec` 被根与子目录 `.gitignore` **有意忽略**，且**三条 workflow 都不用 spec 文件**——
PyInstaller 的参数全部写在 workflow 的命令行里（`--hidden-import` / `--add-data` 一长串）。

这样的好处：参数是 yml 里的**明文可 diff 文本**，由第 1/2 道硬门与 `site_adapters.py`
的清单三方对拍；而 `.spec` 是"另存一份参数"，迟早与 workflow 分叉（分叉后
谁生效看不出来，就是 A 族缺陷的又一个入口）。

**所以**：想改打包参数，改 `.github/workflows/*.yml`（并同步 legacy 的生成器），
**不要**新建 spec 文件。

## 5. `debug/`、`qcollect/`、`qrcode_landing/`：开发资产，不进包

| 目录 | 在库（实测） | 角色 |
| --- | --- | --- |
| `debug/` | 112 份（其中 `.py` 54 份：离线判据套件 27 + `*_test.py` 26 + 施工脚本） | 27 路离线判据 + 探针 + 施工工具（`gen_legacy_workflow.py`、`mutation_check_r6.py`、`mutation_check_r8.py`、`ci_status.sh`、批跑入口） |
| `qrcode_landing/` | 6 份（`deploy_fc.py`、`upload_qr.py`、`fc_handler.py`、`make_banner_qr.py`、`index.html` + 一份自带 `.gitignore`） | 横幅活码：阿里云函数计算部署 + 换图上传。**`group_qr_photo.jpg` 有意不入库**（那是一张能长按识别的现役群二维码，进历史就永久可扫） |
| `qcollect/` | **0 份**（86 份 .py + 日志/页面存盘全在本机） | 历史展会采集脚本堆（一个展会一份 `c_*.py`），与主工具**无 import 关系** |

> **本表原来写的是「`qcollect/`（已跟踪）」——那句话是假的**（2026-11-20 用
> `git ls-files qcollect/` 当场证伪：输出为空）。它属于本段反复出现的那一类缺陷：
> **文档把「这台机器上有」写成了「仓库里有」**，与「验收标准是 65 通过」那句同一个根。
> 本表每一个数字都是实测：`git ls-files -- debug | wc -l`、`git ls-files -- qcollect | wc -l`、
> `find qcollect -name '*.py' | wc -l`。**它们不是一次性核对的**：第 44 条交接闭包门会
> 在每次构建前重跑「文档指路的每个名字是否真的随仓库走」，写的数字漂了门就响。
>
> 为什么 `qcollect/` 不入库而是进 `.gitignore`：它不是交付物（没进任何 workflow/打包清单），
> 内容是已过期展会的单次使用脚本与它们跑出来的页面；把它拉进仓库不会让下一位
> 开发更快，只会让「仓库 = 交付闭包」这个口径再次模糊。换机器真需要它们时，
> 按下面第 6 节「工作区里那些不该带走的东西」的口径处理（整目录自带，不进 git）。
> `backups/`、`b2bcollect_build_backup_*/` 同理进忽略——后者实测 12215 份文件，
> 一次 `git add -A` 就永久进历史，那才是它们进 `.gitignore` 的真正理由（第 44 条乙1）。

`debug/` 里的 `.sh` **全部要在 `SHELL_SOURCES` 登记**（第 15 道门 20e）。
本段实测：新写 `ci_status.sh` 忘了登记 → 当场红；补登记后 20c 又抓出它一个真缺陷
（响应体落盘会留截断 JSON）。**这道登记门的价值就在这两下。**

## 7. 推荐的"发新机器"打包动作

```bash
# ① 先确认交付边界干净（工作区改动都提交了）
git status --porcelain .github b2bcollect_build riskbird_build ali1688_build debug enf_clean docs
#   期望：空

# ② 把第 2 节那 5 份文档入库（一次性，做完这步 clone 就够了）
git add 打包说明.md DeepSeek_API使用指南.md DeepSeek_API智能解析优化总结.md \
        企知道搜索失败问题修复总结_20261105.md 验证码处理优化总结_20261105.md docs/
git commit -m "交接资料入库：5 份历史故障复盘与打包说明 + docs/ 交接文档"

# ③ 推上去；新机器只需 git clone + 02 文档第 3 节两条命令
git push origin main
```

若不方便建远端仓库，用归档拷贝（**按层次二的危险区反向筛**）：

```bash
# 只带「已跟踪 + 第 2 节那几份」，其余全排除
tar --exclude='.venv' --exclude='__pycache__' --exclude='.pytest_cache' \
    --exclude='backups' --exclude='*backup*' --exclude='node_modules' \
    --exclude='*.png' --exclude='*.jpg' --exclude='*.gif' --exclude='*.bmp' \
    --exclude='*.log' --exclude='*_progress.json' \
    --exclude='.git' --exclude='config.json' --exclude='.gh_token' \
    -czf /tmp/handover.tar.gz .
```

> 这个 tar 的排除表与 `02` 第 2 节的 rsync 表**是同一套口径**，两处若改都要改。
> 更稳的做法始终是：**先让 `git clone` 拿得到全部该拿的**（第 ② 步），再不用 tar。

## 8. 一句话原则

> **能再生的一律不进仓库；不能再生的一律进仓库；密钥任何情况下都不进仓库。**
>
> 工作区里那批「未跟踪且未忽略」的文件（就是上面层次二，要数字当场跑）是这个原则
> **没执行到位**的证据——
> 它们既没被 `.gitignore` 明确放弃，也没被提交。危险不在于乱，
> 而在于**总有一天 someone 会 `git add -A`**（根 `.gitignore` 文件头正是为此而生：
> "只要有一次 `git add -A`，`.venv` 或 `.gh_token` 就会进历史——
> 历史里的密钥删不掉，只能作废重发"）。
