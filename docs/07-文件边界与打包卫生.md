# 07 · 文件边界与打包卫生

> 回答两个问题：**发新机器必须带什么** / **工作区那一堆东西哪些能删**。
> 所有数字都是 2026-11-20 实测（附复跑命令）。

---

## 1. 三个层次，先分清楚

```
层次一：仓库里已跟踪 ──────────── 223 份  ← 这才是「项目」，git clone 就能拿到
层次二：未跟踪、也没被 .gitignore 忽略 ── 11,712 份 ← 「危险区」：一次 git add -A 就进历史
层次三：未跟踪、已被 .gitignore 忽略 ─── 99,694 份 ← 可再生物（.venv、缓存、构建中间物）
```

复跑这三个数：

```bash
git ls-files | wc -l                                          # 223
git -c core.quotepath=off ls-files --others --exclude-standard | wc -l   # 11712
git ls-files --others --ignored --exclude-standard | wc -l                 # 99694
```

> ⚠️ **统计中文文件名必须加 `-c core.quotepath=off`**。
> 不加时 git 会把 `打包说明.md` 输出成 `"\346\211\223..."`（**以引号结尾**），
> 于是 `grep '\.md$'` 一条都匹配不上。本段我就踩过：漏统计了根目录全部中文文档，
> 差点得出"根目录没有未入库资料"的错误结论。

已在库的根文档（2 份）：`工具功能清单.md`(110)、`全盘扫描上传执行指令.md`(119)。

**入库前先读 `.gitignore` 的原则**（写在文件头）：
> 只拦「可再生」和「不该外传」两类；采集到的数据、模板、脚本一律不拦，

上述 5 份都属于"用户要保存的东西"，但**我先前写的「不含密钥」是错的**（2026-11-20 复核）。
文档卫生扫描在其中 3 份里各抓到**一枚真实 DeepSeek Key**：`DeepSeek_API使用指南.md`、
`DeepSeek_API智能解析优化总结.md`、`验证码处理优化总结_20261105.md`。三份都已就地打码，
真值只留在 `b2bcollect_build/config.json`（那份被 `.gitignore` 拦着，不在可提交范围内）。

因此入库的正确顺序是**先过第 43 条、再 `git add`**：

```bash
.venv/bin/python .github/scripts/check_packaging_manifest.py    # 看「密钥泄漏防线」那一格
```

那三枚当时还没进过任何提交（按值在全历史里检索为空），所以只改文件就来得及。这个运气
不能用第二次：**进了历史的密钥删不掉，只能去控制台作废重发**——这就是把这一格前置的全部理由。
同一天首跑该门，又抓到三处 `os.environ.get('OSS_ACCESS_KEY_ID', '真实 ID')` 形态的硬写兜底
（`qcollect/zz_ossupload.py`、`qrcode_landing/deploy_fc.py`、`qrcode_landing/upload_qr.py`），

## 3. 依赖清单：三份，**有意不同**，别"顺手统一"

| 清单 | 谁读它 | 内容差异 |
| --- | --- | --- |
| `.github/requirements/b2bcollect.txt` | **单一真源**：`pip_install.py` 与本机都读 | 全量 11 项（含 pyinstaller/phonenumbers/xlrd） |
| `b2bcollect_build/requirements.txt` | 给人手装的**子集** | 8 项，带 `>=` 版本约束，**无 pyinstaller/phonenumbers/xlrd** |
| `.github/requirements/riskbird.txt` | RiskBird 那个工具 | **仍含 pandas**（减重只针对 b2bcollect） |
| `.github/requirements/build-1688.txt` | Ali1688 那个工具 | 5 项最小集 |

三条不能改的点：
1. **别把 b2bcollect 的 pandas 加回去**——需求 5 已实证：产物里没有任何运行路径用得到
   DataFrame，而它连带 numpy 约 27MB 白拿。清单里那段注释还写着更狠的理由：
   > 不把这一行留在装环境里是有意的：装了它就等于等某人在进包的模块里写一句
   > `import pandas`，PyInstaller 会安静地把它再拉回产物，而**体积回弹不会有任何一步报错**。
2. **别删 `phonenumbers`**——它是 `enf_clean/phone.py:14` 经
   `enhanced_cleaner.py:36-40` 进入运行链的**真依赖**（见 `01` 第 1.1 节）。
   本段交接复核时我曾误判它"只被未入库目录使用"，差一点写进文档。
3. **别删 `xlrd`**——**真在用**（读老 .xls），曾被误判成残留。

第 39 道门 `check_requirements_coverage` 在盯"清单与进包闭包是否覆盖一致"。

## 4. `*.spec` 为什么不在仓库里（不是遗漏）

`*.spec` 被根与子目录 `.gitignore` **有意忽略**，且**三条 workflow 都不用 spec 文件**——
PyInstaller 的参数全部写在 workflow 的命令行里（`--hidden-import` / `--add-data` 一长串）。

这样的好处：参数是 yml 里的**明文可 diff 文本**，由第 1/2 道硬门与 `site_adapters.py`
的清单三方对拍；而 `.spec` 是"另存一份参数"，迟早与 workflow 分叉（分叉后
谁生效看不出来，就是 A 族缺陷的又一个入口）。

**所以**：想改打包参数，改 `.github/workflows/*.yml`（并同步 legacy 的生成器），
**不要**新建 spec 文件。

## 7. 推荐的"发新机器"打包动作

```bash
# ① 先确认交付边界干净（工作区改动都提交了）
git status --porcelain .github b2bcollect_build riskbird_build ali1688_build debug enf_clean docs
#   期望：空

# ② 把第 2 节那 5 份文档入库（一次性，做完这步 clone 就够了）
git add 打包说明.md DeepSeek_API使用指南.md DeepSeek_API智能解析优化总结.md \
        企知道搜索失败问题修复总结_20261105.md 验证码处理优化总结_20261105.md docs/
git commit -m "交接资料入库：5 份历史故障复盘与打包说明 + docs/ 交接文档"

# ③ 推上去；新机器只需 git clone + 02 文档第 3 节两条命令
git push origin main
```

若不方便建远端仓库，用归档拷贝（**按层次二的危险区反向筛**）：

```bash
# 只带「已跟踪 + 第 2 节那几份」，其余全排除
tar --exclude='.venv' --exclude='__pycache__' --exclude='.pytest_cache' \
    --exclude='backups' --exclude='*backup*' --exclude='node_modules' \
    --exclude='*.png' --exclude='*.jpg' --exclude='*.gif' --exclude='*.bmp' \
    --exclude='*.log' --exclude='*_progress.json' \
    --exclude='.git' --exclude='config.json' --exclude='.gh_token' \
    -czf /tmp/handover.tar.gz .
```

> 这个 tar 的排除表与 `02` 第 2 节的 rsync 表**是同一套口径**，两处若改都要改。
> 更稳的做法始终是：**先让 `git clone` 拿得到全部该拿的**（第 ② 步），再不用 tar。

## 8. 一句话原则

> **能再生的一律不进仓库；不能再生的一律进仓库；密钥任何情况下都不进仓库。**
>
> 工作区里 11,712 份"未跟踪且未忽略"的文件是这个原则**没执行到位**的证据——
> 它们既没被 `.gitignore` 明确放弃，也没被提交。危险不在于乱，
> 而在于**总有一天 someone 会 `git add -A`**（根 `.gitignore` 文件头正是为此而生：
> "只要有一次 `git add -A`，`.venv` 或 `.gh_token` 就会进历史——
> 历史里的密钥删不掉，只能作废重发"）。
