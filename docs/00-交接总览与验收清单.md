## 1. 这个工具是什么（一句话 + 三层）

一个 **PyQt5 桌面工具**，从 8 个 B2B 平台批量采集企业工商信息与联系方式，
清洗后导出 Excel；带**账号权限分级**、**自动更新**、**数据池**、**AI 辅助**四块支撑能力。

| 层 | 位置 | 职责 |
| --- | --- | --- |
| 界面与调度 | `b2bcollect_build/` | 主程序 `b2bcollect_gui.py`、并行会话、数据池、权限、清洗、导出 |
| 跨目录复用的爬虫内核 | `riskbird_build/` `ali1688_build/` | Chrome 驱动治理、反爬守卫、1688 与企知道等采集器 |
| 交付链 | `.github/` `debug/` | GitHub Actions workflow、构建脚本、构建前硬门、全量离线回归（这四类**各有多少份/条/路，本文一律不抄**，取数命令见 `03` §1-§2 —— 旧版在这里抄过一次，交接当天就已过期） |

同一仓库里还住着**另外两个可独立打包的工具**（RiskBird、Ali1688），
它们与 b2bcollect 共享爬虫内核，各自有 workflow 与依赖清单。见 `07-文件边界`。

## 3. 新机器（M4 Mac）搭建 —— 硬性前提

详细步骤与逐条理由见 `02-新机器搭建-macOS-M4.md`。这里只列**不能妥协**的三条：

1. **Python 版本**：一个现代 CPython 就够开发（本机 3.13.7 实测跑得完全量离线回归）。
   **不需要在 Mac 上装 Python 3.8**——这是本段交接复核时差点写进文档的一个错：
   Win7 兼容通道的双解释器（目标 3.8 + 工具链 3.11）只由**云端 Windows runner** 用
   `actions/setup-python` 安装（`build-b2bcollect-legacy.yml` 第 64-86 行）；本机的 frozen
   套件是拿 `sys.executable` 同时当两个参数、故意造一个「分工不成立必须退 1」的冒烟
   （`test_frozen_delivery_offline.py` DG 组 4）。**本地硬装 3.8 在 arm64 上是个坑，且毫无收益。**
2. **依赖只认一份清单**：`.github/requirements/b2bcollect.txt`（单一真源）。
   `b2bcollect_build/requirements.txt` 是**给人手装的子集**，两者有意不同，
   差异与原因写在 `07-文件边界` 第 3 节 —— 别"顺手统一"，那会删掉打包机的 pyinstaller。
3. **不要 `git add -A`**：根 `.gitignore` 是防呆层，拦的是 `.venv/`、`config.json`、
   `.gh_token`、`version.json` 等。历史里的密钥删不掉，只能作废重发。

上面两栏是 **2026-11-20 实测快照**，只用来看出结构（代码主体在 `b2bcollect_build/`，

**不要当作“现在到底多少份”的答案**。

工作区实测共 **8.6 GB**，但交付边界只占其中很小一块（大头是 `.venv/` 741MB、
`.git/` 218MB）。另有**大量未跟踪产物**：截图、探针 HTML、各 `*_run.log`、
`backups/`、`b2bcollect_build_backup_20261106/`、若干 `scrape_*.py` 单站脚本。
**它们不在交付边界内**。

> 上一版本这里写着「里面混着少量其实该入库的文档（如 `打包说明.md`）」。
> 2026-11-20 已全部办完：`docs/` 8 份、`.qoder/rules/` 4 份、`AGENTS.md`、

所以现在的口径变了：**直接 `git clone` 就能拿到全部代码、判据、夹具与交接文档**；
剩下只能带外传的只有凭据那一份（`b2bcollect_build/config.json`，被 `.gitignore` 拦着，
见 `02` 第 6 节）。反过来，整目录拷贝仍不可取：会把未入库的截图、

## 6. 接手后的第一件事（按优先级）

1. **先把本地提交推上去**：`git push origin main`。兼容通道的 PE 门修复（`5eace9e`）与
   交接闭包两批（`839114f`、`2298fd9`）都只在本地时，云端那三条流水看到的还是旧提交，
   后面每一项都会被这件事卡在门口（本段实测：#3 从未产生，不是又红了，是根本没跑）。
   推完再盯那一路：目标是产出 `B2bCollectToolSetup_Win7.exe`，看红先看第 14 步。
2. **补 `sm_binary()` 的离线判据**：`riskbird_build/chrome_driver.py` 的三态口径
   （present / absent / unknown）目前**没有判据保护**——代码是对的，但下一次改动
   很容易把它退回"把测不到当没有"那个更坏的形态。这是本段已知的**唯一一处裸奔新代码**。
3. **需求 10C**：单一链接自动选包（给小白一个 URL，按系统自动发 Win7/Win10/Mac 包）。
   依赖第 1 项完成。
4. 其余未完成项与已知缺陷见 `05-需求台账与未完成项.md`。

**规则**在 `.qoder/rules/`；`AGENTS.md` 在仓库根。四份规则文件与本文不重复：
本文讲**事实与现状**，规则文件讲**不许做什么**。

> 这里**不写「IDE 会自动加载规则」这种话**：本仓库的取证机是 Qoder IDE，而接手方是同一台
> 机器上的 Qoder CN IDE，两者的状态目录实测互相隔离（`~/.qoder` 与 `~/.qoder-cn`），
> CN 侧会不会读 `.qoder/rules/` **没有实测证据**。所以 `08` 的开场话术里把「手动读完四份规则」
> 写成了第一步——交接的正确性只能锚在「仓库里的文件 + 显式让它读」，不能锚在客户端特性上。
> 想当场验证：新会话里问一句「本项目 `.qoder/rules/` 下有几份规则文件、分别讲了什么」，
> 答不出就是没自动加载，照话术手动读。
