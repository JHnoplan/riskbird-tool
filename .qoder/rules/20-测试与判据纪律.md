# 测试与判据纪律（这里的规则决定判据可不可信）

## 两套闸门，分工不同

| | 硬门（构建前） | 离线判据（回归） |
| --- | --- | --- |
| 入口 | `.github/scripts/check_packaging_manifest.py` | `bash debug/run_offline_regression.sh` |
| 盯什么 | 结构完整性：清单/闭包/参数一致、路径、编码、shell 卫生 | 行为正确性：解析、清洗、状态机、界面、退出时序 |
| 耗时 | 秒级，**每次改交付链都跑** | 分钟级（frozen 那一路占大头），**收口前必须全量** |

## 写判据的硬要求

1. **空视野必须自己红。** `check_xxx([])` 返回"没有不合格"是一句谎话——读不到文件、扫到 0 条、
   登记的资源不在位，都要报红，不许静默通过。
2. **区分"没扫到"和"扫过且合格"。** 报绿时要能说清扫了什么（份数/来源），否则判据是空的。
3. **反向对照要真响。** 每条正向断言旁边要有"喂一份坏的进去必须响"的夹具；
   并且要验**归属干净**：喂一份坏的只响那一份，不是一锅糊结论。
4. **判定行不许裸 `print`。** 必须走计数器，否则总数失真，"3357 通过"这种数不可信。
5. **失败信息要能定位。** 点名文件、行位、期望/实际；只写"检查失败"等于让人重跑一遍猜。
6. **不要打全量大对象。** 通过时也 `!r` 打印两侧，会把日志灌到几十 KB 埋掉真信息；
   比对大字节串时报**首个差异字节号**即可。
7. **注释里的"见第 N 条"必须走得到。** 指路节号失效有专门一道门在判（第 12 条）。

## 变异复验（新判据的验收动作，不可跳）

```
把修复逐个退回原样 → 对应判据必须精准变红 → 逐字节还原（git diff 必须空）→ 复跑回全绿
```

- 变红必须**对应到那一条判据**；不红 = 判据没在工作（本项目靠这一步逮出过 N2/N4 等多条假绿）。
- 多个分支被一条模糊子串断言同时覆盖 = 分不清哪条放的红 = **假绿**，要拆成各自钉死。
- 判据切片**不许跨步骤**：取一个函数的正文就只取那一个，跨步切片会把合法代码当嫌疑对象（假红）。

## 批跑相关

- 交付目录（`b2bcollect_build` / `riskbird_build` / `ali1688_build`）里
  **命名成 `test_*_offline.py` 就自动进批跑**，不需要谁记得登记；`debug/` 下命名不齐，
  手写清单但有完整性判据（"磁盘上有、表里没有"当场红并拒绝开跑）。
- 缺实机夹具的套件必须如实报 **SKIP-FIXTURE**，不许混进 FAIL——长期红着的一项会淹掉真问题。
- 单跑几套：`B2B_REGRESSION_ONLY="路径" bash debug/run_offline_regression.sh`
  （其余判据一条不少；这个口子是为了能注入"故意会红"的夹具验活批跑入口自己）。
- **抖动必须根治，不许加重试**：让断言依赖的"地标"显式化（排队投递、心跳停止），
  重试会把真缺陷平均掉。
- 碰过 Qt 的套件收尾要按第 17 道门：`rc = app.exec_()` → 主窗口 `hide()` + 置 `None` → `sys.exit(rc)`；
  需要时 `flush` + `os._exit`。写成 `sys.exit(app.exec_())` 会让退出码随机 139。

## 定位一条红的标准流程

1. 看批跑汇总点名的那一行，再去 `debug/regression_logs/logs/<套件名>.log` 看完整输出。
2. **先定性**：是代码错了、判据过时了、还是"改了没提交"（这一类提交后自动归零）。
3. 不许"改判据让它绿"就收工；要改判据必须在提交信息里写清依据。
4. 门给的修法如果要求重跑某个生成器，先确认**生成器本身在提交里**（否则干净克隆里跑不了）。
