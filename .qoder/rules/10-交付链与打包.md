# 交付链与打包（改这一层前必读）

## 平台边界（先接受，再动手）

- **PyInstaller 不做交叉编译**：Windows 包只能由云端 `windows-latest` runner 产出，
  macOS 包可由本机 `bash debug/build_b2bcollect_mac_local.sh` 产出。
- 改 Windows 交付链的正确姿势：**推到 `main`，看云端那一步的日志**，不要在本机模拟成功就当验过。
- 本机**不需要**装 Python 3.8/3.11：双解释器只存在于兼容通道 workflow 里（由 `actions/setup-python` 现装）。
  本地 frozen 判据是故意拿同一个解释器同时当两个参数，来验"分工不成立时必须退 1"。

## 五条 workflow，职责别混

| 文件 | 产出 |
| --- | --- |
| `.github/workflows/build-b2bcollect.yml` | 主通道 Windows 安装包 |
| `.github/workflows/build-b2bcollect-mac.yml` | macOS `.app` |
| `.github/workflows/build-b2bcollect-legacy.yml` | Win7 兼容包（双解释器，**由生成器产出**） |
| 其余两份 | 另两个工具 / 辅助用途 |

改 `build-b2bcollect-legacy.yml` **必须改 `debug/gen_legacy_workflow.py` 再重跑生成器**——
判据会钉"生成器输出与 yml 逐字节相同"，手改 yml 必红。

## 打包参数只有两处真相

1. `.github/workflows/*.yml` 里的 `--hidden-import` / `--add-data` / `--exclude-module` 命令行；
2. `.github/scripts/check_packaging_manifest.py` 里的清单常量（闭包、白拿名单、成分账）。

**不许新建 `*.spec`**（被 `.gitignore` 有意忽略，三条通道都不用 spec）。
新增进包模块要同时落到：workflow 参数、硬门清单（`module_manifest` / `EXTERNAL_MODULES` /
`NOT_PACKAGED`）、以及对应站点适配器——三处对拍由第 1/2 道硬门负责，少一处就红。

## 依赖清单：三份**有意不同**，不要"顺手统一"

- `.github/requirements/b2bcollect.txt` = **单一真源**（云端与本机都读它，11 项全量）。
- `b2bcollect_build/requirements.txt` = 给人手装的**子集**（无 pyinstaller / phonenumbers / xlrd）。
- `.github/requirements/riskbird.txt` = 另一个工具，**仍含 pandas**（减重只针对 b2bcollect）。

三条不可改点见 `AGENTS.md` 第 4 节；第 39 道门 `check_requirements_coverage` 在盯覆盖一致性。

## 构建前后各有一面重量门

```bash
# 构建后那一面（产物目录实测），三个打包入口都调它，参数别自创
cd b2bcollect_build && python ../.github/scripts/check_packaging_manifest.py \
  --prune-artifact dist/B2bCollectTool --artifact-weight dist/B2bCollectTool --artifact-label "Mac"
```

体积回弹**不会有任何一步自动报错**——所以清单里不留 pandas 是"有意的防线"，不是清理遗漏。

## 发布与更新链

- 版本号唯一真源：`b2bcollect_build/tool_version.py`；`version.json` 由 CI 现生成，**绝不入库**。
- 发版清单 / 固定直链 / 下载校验：`make_release_manifest.py`、`download_verify.py`、`tool_update.py`。
- 密钥走 GitHub Secrets 或用户目录，**任何情况下不进仓库、不进聊天、不进提交信息**。
- 看三条通道跑到第几步：`bash debug/ci_status.sh`（红话给的下一步：`debug/fetch_run_log.sh <run_id>`）。

## 老系统与运行库

- 任何"能不能在 Win7 跑"的结论必须有**实测把手**：PE 子系统地板由 `check_pe_floor.py` 从产物字节里量，
  解释器地板由第 42 条双解释器体检验。**窗口冒烟与导入表都看不出 `api-ms-win-core-path` 这类延迟加载。**
- 缺 VC++ 运行库由安装器随包补装；老系统 ChromeDriver 版本由 `fetch_chromedrivers.py` 按地板封顶。
- 新增"缺文件就报错"的用户环境问题，优先做**安装时自动补齐**，而不是写进"用户手册"。
