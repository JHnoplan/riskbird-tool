# 代码与用户可见文案（按文件生效）

## 语法地板：**进包的代码必须能被 Python 3.8 读懂**

Win7 兼容通道用 3.8 解释器打进包，第 42 条会按进包闭包逐份用 3.8 解析。因此：

| 位置 | 允许的语法 |
| --- | --- |
| 进包闭包（`b2bcollect_build` / `riskbird_build` / `ali1688_build` / `enf_clean` 及它们 import 的一切） | **只到 3.8**：禁 `match`、禁 `X | Y` 类型注解、禁 `dict1 | dict2` 合并 |
| 门禁与工具脚本（`.github/scripts`、`debug`） | 可到门禁地板（`check_packaging_manifest.py` 用了 `ast.unparse`，需 3.9+） |

拿不准就查：`.venv/bin/python .github/scripts/check_packaging_manifest.py` 第 34 / 42 条会直接点名。

## 文本 IO 与子进程（第 10 条在判）

```python
# ✗ 不合格：text=True 不写 encoding —— 换台机器 locale 就解出乱码
subprocess.run(cmd, capture_output=True, text=True)
# ✓ 合格
subprocess.run(cmd, capture_output=True, text=True, encoding="utf-8", errors="replace")

# ✗ 不合格：open() 不写 encoding
open(path).read()
# ✓ 合格
open(path, encoding="utf-8").read()
```

写文件同理；读外部来源（网页、用户机器上的文件）要显式 `errors=` 或先探测，
不要假设 UTF-8。控制台输出也要考虑非 UTF-8 终端（Windows 控制台是这一族的高发地）。

## 用户可见文案

- 界面、日志、报错话术一律**中文**；专业术语与代码标识符保留原文。
- **报错要说人话并给出下一步**：这是哪一步、为什么失败、现在能怎么办。
  不要把内部实现名词（模块名、变量名、堆栈）直接甩给终端用户。
- 状态分三格表述：**确认没有** / **读不出** / **没东西可实测**，措辞不许混用
  （"没检测到"和"不存在"不是一句话，前者可能只是没看到）。
- 面向电脑小白的路径：能自动补齐的不要写成"请手动安装 XX"。

## 结构与复用

- 站点采集走适配器体系：`parallel_session.py` 的 `SITE_ORDER` / `SITE_CLASSES` / `SITE_NAMES`
  **三处必须同步**（少一处就是"某平台永远不跑"的静默失效），并同步 workflow 参数与硬门清单。
- 跨目录复用模块要登记在 `site_adapters.EXTERNAL_MODULES`；**同名模块在不同目录就是两份真相**，
  第 23 道门（模块名绑定）与第 9 道门（大小写撞名）会判。
- 一个事实只写在一个把手里：常量、路径、清单、计数器都不许抄第二份。
- 注释密度与命名跟随周边代码；**注释要写"为什么"和由来**（本仓库的注释普遍带故障日期与依据）。

## 崩溃与取证链（需求 8 立的规矩）

- `crash_forensics.py` 及其钩子**自身必须零抛出**——取证工具把程序带崩是最讽刺的失败形态。
  任何钩子里的代码都要能容纳"拿不到数据""编码坏了""对象已析构"。
- 往表格/导出里塞外部数据前要过根因把手（`text_shape.cell_text` / `cell_join`），
  非字典记录要有兜底；入库前要脱敏。
- `main()` 里装钩子要早于任何可能抛出的工作；queued 槽位用 `slot_guard` 包，
  Worker 要兜异常并发失败信号，不许让异常静默吞掉一个任务。
