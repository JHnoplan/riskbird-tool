# 项目铁律（始终生效）

本项目是 **B2B 采购商信息采集工具**（PyQt5 桌面程序 + 三份安装包交付物）。
交付链由**构建前硬门 + 全量离线判据**保护（条数与路数一律用 `docs/03` §1-§2 的命令现取，规则文件里不抄），它们全部来自真实故障。以下八条是这些故障的浓缩，
违反其中任何一条都会造成"本机全绿但用户装不上 / 打不开 / 静默少功能"这类最贵的缺陷。

## 收口顺序（固定，不许跳步）

改代码 → **构建前硬门** → **全量离线批跑** → 提交 → 推送 `origin/main` → 看云端流水线 → 打开工具给人验。

```bash
.venv/bin/python .github/scripts/check_packaging_manifest.py   # 硬门，秒级
bash debug/run_offline_regression.sh                          # 全量批跑（分钟级，路数由脚本自己展开）
```

命令口径的单一真源在 `AGENTS.md` 第 2 节；细则在 `docs/03`。不要在别处另抄一份命令。

## 八条不可让步的约束

1. **本机绿 ≠ 交付绿。** 门与 CI 判定的是**提交态**。工作区改了没 commit 就跑绿，结论对交付没有担保。
2. **不确定时分三格**：`确认没有` / `读不出` / `没东西可实测`。**只有"确认没有"允许拦停**。
   把"测不到"当成"没有"是本项目代价最高的一族缺陷。写判断分支时先问：我现在是哪一格？
3. **新判据必须能被打红。** 判据写完立刻做变异复验：把修复退回原样 → 对应判据必须精准变红
   → 逐字节还原（`git diff` 必须空）→ 复跑回全绿。从未红过的判据等于没有判据。
4. **同一事实只许一个把手。** 判定行不许绕开计数器裸 `print`；路径、失败原因、进度提示都只许一处产生。
5. **交付链里不许出现开发机绝对路径。** 定位自身按脚本位置算；探测环境要探测**能力**
   （如 `import PyQt5` 能否成功），不是探测"文件在不在"。
6. **"存在"不等于"本平台可执行"。** 任何找二进制的代码都要过这一问。
7. **报错要能照着做。** 必须点名文件、行位、期望与实际，并给出下一步命令；只 print 不改退出码的门无效。
8. **`git add -A` 禁止。** 工作区有上万份未跟踪未忽略的文件，误提交会连带密钥与 `.venv`。
   提交前先 `git status` 亲眼看过。

## 禁止改动的东西（每条都对应一次真实事故）

- 不要把 `pandas` 加回 `.github/requirements/b2bcollect.txt`（连带 numpy 约 27MB 白拿）。
- 不要删 `phonenumbers`、`xlrd`，不要动 `enf_clean/`——都是**进包运行期真依赖**，删了是静默降级。
- 不要新建 `*.spec`：打包参数只写在 `.github/workflows/*.yml`，spec 是第二份真相。
- 不要提交 `version.json`、`config.json`、任何 token（版本文件由 CI 现生成）。
- 不要为了消红而放宽"总数钉死型"断言——正解是把新增那一路**点名登记**进表。
- 不要把 `backups/`、`b2bcollect_build_backup_*/` 当事实（已删平台的旧快照，专门骗 grep）。
- 不要用重试掩盖批跑抖动；不要改判据去迁就代码（先定性再动手）。

## 工作方式（用户明确要求）

- **全程用中文描述**在做什么、为什么、到哪一步；长任务要主动报进度。
- **自审要产出证据**："我检查过了"不算，要**换一个采集口径重取一次**（例：grep 完 `import`
  还得查 `--add-data` / `--hidden-import`；统计中文文件名必须加 `-c core.quotepath=off`）。
- 按需求**分批提交**，提交信息写**由来**，不写 "fix bug"。
- 代码注释、日志、界面文案、报错话术一律中文；专业术语与标识符保留原文。
